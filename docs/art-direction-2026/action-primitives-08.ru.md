# Tallshift UI / 08 — действия и вкладки

Это общие React-компоненты и интерактивные образцы, а не утверждение о готовности всей библиотеки. Источник: `prototype/src/foundations/`.

## SystemButton

`SystemButtonProps` расширяет `ComponentPropsWithRef<'button'>`. React 19 `ref` передаётся в нативную кнопку. `type` по умолчанию `button`; отправку формы нужно явно включить через `type="submit"`.

- `variant`: `primary | secondary | quiet | destructive`, по умолчанию secondary.
- `size`: `small | medium | large`: минимальная высота 44 / 48 / 52 px. Средние внутренние отступы 11 × 16 px во всех вариантах, включая quiet.
- `loading`: фиксирует текущий текст и размеры, показывает индикатор и выставляет `aria-busy` / `aria-disabled`. Кнопка сохраняет фокус и доступное имя. Повторный click блокируется. Текст состояния для live region остаётся обязанностью вызывающего кода.
- `leadingIcon`, `trailingIcon`: декоративные элементы с `aria-hidden`.
- Нативный `disabled`: исключает действие и фокус. Причину необходимо вывести рядом и связать через `aria-describedby`.
- `aria-disabled` также блокирует вызов onClick. Это не замена бизнес-проверке состояния операции в обработчике формы.

Индикатор не крутится при системном reduced motion или внутри `data-motion="off"`. Цвет фокуса нейтральный, не жёлтый. Forced colors использует системные цвета.

`SystemIconButton` принимает тот же API, обязательные `icon: SystemIconName` и `label: string`; зона нажатия квадратная 44 / 48 / 52 px. Toggle задаётся нативным `aria-pressed`; компонент не хранит состояние за вызывающий код. Пустой label недопустим. Tooltip не заменяет label.

## SystemTabList и SystemTabs

`SystemTabList<T extends string>` нужен существующим панелям, чей жизненный цикл и раскладку менять нельзя:

```tsx
<SystemTabList
  label="Component resources"
  value={view}
  onChange={setView}
  activation="automatic"
  options={[
    { value: 'demo', label: 'Preview', tabId: 'tab-demo', panelId: 'panel-demo' },
    { value: 'source', label: 'Code', tabId: 'tab-source', panelId: 'panel-source' },
  ]}
/>
```

Вызывающий код создаёт panel с `role="tabpanel"`, уникальным `id`, `aria-labelledby=tabId`, и исключает неактивные панели из фокуса и дерева доступности. Автоматический режим уместен для мгновенно доступных панелей. При дорогой загрузке выбирают `activation="manual"`.

`SystemTabs` добавляет к тому же API `options: { value, label, content, disabled? }[]` и самостоятельно связывает панели. Все панели смонтированы в одной ячейке grid; высота резервируется по самой высокой. Неактивные панели имеют inert, aria-hidden и visibility:hidden. Это сохраняет локальное состояние формы при переключении. Это не lazy-loading контейнер: запросы/эффекты в неактивном content требуют отдельного управления владельцем.

Общее поведение:

- `label`, контролируемые `value` / `onChange`; значения и IDs должны быть уникальны.
- `activation`: automatic (по умолчанию) или manual. В manual стрелки меняют только фокус, Enter / Space выбирают вкладку.
- `orientation`: horizontal (по умолчанию) или vertical. Стрелки соответствуют ориентации; Home / End ведут к первой / последней доступной вкладке. Края зациклены, disabled пропускаются.
- Roving tabindex: только одна доступная вкладка в порядке Tab. После выхода из tablist точкой повторного входа становится выбранная вкладка.
- Длинные горизонтальные подписи не сжимаются до нечитаемого текста: список прокручивается по горизонтали. Вертикальные подписи переносятся.
- Если текущее значение стало недоступно, визуально выбирается первая доступная вкладка. Владелец должен синхронизировать контролируемое value, если от него зависят внешние данные.
- В текущем контракте нет RTL-раскладки. EN, RU и VI используют LTR.

## Интерактивный образец

`ActionSpecimen({ locale, motionOff? })`, anchor `#actions`: общие отступы и варианты, размеры, локальное удаление/восстановление, toggle, вручную запускаемое и завершаемое ожидание, явно недоступное действие, auto/manual/vertical tabs. Нет имитации серверного сохранения, загрузки пакета или таймера с выдуманным прогрессом.

## Проверка и ограничения

TypeScript-проверка выполнена. Браузерные клавиатурные и визуальные проверки выполняются при интеграции стенда; они не заменяют ручную проверку screen reader и нескольких браузеров. Миграция всех старых локальных кнопок и вкладок в эти компоненты — отдельный шаг; наличие API не означает завершение миграции.
