## 03 · SystemIcon

Источник: `prototype/src/foundations/SystemIcon.tsx`, `system-icons.css`.

```ts
type SystemIconName = typeof systemIconNames[number];
interface SystemIconProps {
  name: SystemIconName;
  size?: 16 | 20 | 24; // default 20
  label?: string;
  className?: string;
}
```

Общий контурный набор из 30 иконок: search, close, chevron-down/up/right/left, arrow-left/right, check, copy, download, code, prompt, play, pause, replay, settings, filter, grid, desktop, tablet, mobile, info, warning, error, plus, minus, external, folder, file. Экспорт `systemIconNames` задаёт инвентарь для образца и проверки покрытия.

Единая сетка 24 × 24, круглые окончания и соединения, цвет `currentColor`. Оптическая компенсация толщины в координатах SVG: 16 px → 1.9, 20 px → 1.75, 24 px → 1.6. Размер SVG не определяет размер интерактивной цели; кнопка остаётся не меньше 44 px. Для status и directional используются явные имена и отдельные рисунки; цвет не заменяет подпись.

Без `label` SVG декоративный: `aria-hidden=true`, не фокусируется. Непустой `label` создаёт именованный `role=img`. Пустой или пробельный label трактуется как отсутствие имени. Компонент не принимает обработчики клика и не создаёт действие. У кнопки только с иконкой собственный `aria-label`; подпись самой SVG не заменяет имя кнопки. SVG не использует `title` как единственный способ именования.

```tsx
<button type="button" aria-label="Download source">
  <SystemIcon name="download" size={20} />
</button>
<SystemIcon name="warning" label="Warning" size={24} />
```

Проверить на стенде: полный инвентарь 16/20/24; ровное визуальное положение рядом с текстом; отсутствие обрезки; назначение понятно вместе с локализованной подписью; декоративные SVG отсутствуют в доступном дереве; значимые иконки имеют имя; forced colors сохраняет контур. Миграция локальных SVG выполняется отдельно и не считается завершённой по наличию нового файла.

`IconSpecimen({ locale: 'en' | 'ru' | 'vi' })`, якорь `#icons`, показывает все 30 имён и переключение 16/20/24 без изменения размера ячеек. Иконки рядом с видимыми именами декоративные. Список раскрыт по умолчанию и может быть свёрнут.

## 16 · SystemSegmentedControl

Источник: `prototype/src/foundations/SystemSegmentedControl.tsx`, `system-segmented-control.css`.

```ts
interface SystemSegmentedOption<Value extends string = string> {
  value: Value;
  label: string;
  ariaLabel?: string;
  lang?: string;
  disabled?: boolean;
}
interface SystemSegmentedControlProps<Value extends string = string> {
  label: string;
  value: Value;
  options: readonly SystemSegmentedOption<Value>[];
  onChange: (value: Value) => void;
  disabled?: boolean;
  orientation?: 'horizontal' | 'vertical'; // default horizontal
}
```

Контролируемый выбор одной настройки. Родитель хранит `value` и применяет результат `onChange`; компонент не меняет URL, не управляет панелями и не изображает вкладки или навигационные ссылки. Значения опций должны быть уникальными, подписи непустыми. Отсутствующее в опциях `value` оставляет группу без выбранной опции, без скрытого исправления данных и вызова callback. Пустой список не создаёт фиктивную опцию.

Нативные radio с единым уникальным `name` внутри fieldset. `useId` связывает legend и имя radiogroup; экземпляры не влияют друг на друга. Стрелки и Space работают по нативной модели radio, Tab переходит между группой и остальными элементами. Недоступные опции пропускаются браузером. `onChange` вызывается только при настоящем изменении выбранного radio; mount и изменение внешнего `value` не вызывают callback.

`ariaLabel` задаёт развёрнутое имя для короткой видимой подписи: EN → English, RU → Русский, VI → Tiếng Việt. `lang` задаёт язык подписи соответствующей опции. Оба свойства необязательны; обычные подписи получают доступное имя через label.

Все доступные сегменты занимают равные колонки `minmax(0, 1fr)` и не меняют толщину рамки или вес шрифта при выборе. Минимальная высота цели — 44 px. Длинные подписи EN/RU/VI переносятся и увеличивают общий ряд по самому высокому сегменту, без обрезки и горизонтального переполнения. Вертикальный вариант складывает равные по высоте сегменты в одну колонку. Порядок DOM не изменяется. Нейтральный focus `--f-focus` отделён от выбранного Saffron-состояния; hover, pressed, disabled и checked имеют отдельные правила. Движение ограничено цветом и отключается при глобальном Off и системном reduce.

```tsx
type PreviewSize = 'full' | 'tablet' | 'mobile';
const options = [
  { value: 'full', label: 'Desktop' },
  { value: 'tablet', label: 'Tablet' },
  { value: 'mobile', label: 'Mobile' },
] as const;

<SystemSegmentedControl<PreviewSize>
  label="Preview width"
  value={width}
  options={options}
  onChange={setWidth}
/>
```

При необходимости компактного встраивания родитель может визуально скрыть `.system-segmented-label` обычной техникой visually-hidden, сохраняя имя группы; `display:none` и `aria-hidden` для legend не применять.

Проверить на стенде: выбор pointer/touch/Space и стрелками; один Tab-stop для выбранной группы; disabled-опция и disabled-группа; независимость двух экземпляров; selected и focus одновременно различимы; одинаковая высота при переключении; длинные RU/VI подписи на 320 px и zoom; горизонтальный и вертикальный варианты; forced colors; Off/reduce; сохранность выбранного значения при смене языка и размера preview.

Раздел состояний `IconSpecimen` раскрывается отдельно: обычная группа меняет выравнивание реального локального образца, disabled-группа не реагирует, вертикальная группа с длинными EN/RU/VI подписями перестраивает пару preview/code. Вариант отдельного окна явно недоступен. Все это локальные образцы API, не второй редактор экспортируемого материала. Общая проверка `./node_modules/.bin/tsc -b` прошла; browser/device-приёмка выполняется после встраивания в стенд.

## 09 · SystemSearchCombobox

Источники: `prototype/src/foundations/SystemSearchCombobox.tsx`, `system-search-combobox.css`; встраивание — `DiscoveryLab.tsx`, фильтрация — `discovery-filter.ts`.

```ts
interface SystemSearchOption {
  value: string;
  label: string;
  detail?: string;
  meta?: string;
}
interface SystemSearchComboboxProps {
  label: string;
  placeholder: string;
  value: string;
  onChange: (value: string) => void;
  onSelect?: (option: SystemSearchOption) => void;
  options: readonly SystemSearchOption[];
  clearLabel: string;
  listLabel: string;
  emptyText: string;
  hint?: string;
  locale?: string;
  disabled?: boolean; // default false
  inputRef?: React.RefObject<HTMLInputElement | null>;
}
```

Контролируемый текстовый поиск с синхронными локальными подсказками. Родитель хранит строку `value`, передаёт уже отфильтрованный и упорядоченный массив `options`, локализует все видимые подписи. `value` опции должен быть уникальным; `label` содержит строку, которая попадёт в поле при выборе. `detail` и `meta` — дополнительные текстовые сведения, а не отдельные действия. Компонент не выполняет повторную фильтрацию, сетевой запрос или переход к материалу.

Ввод вызывает `onChange` с текущим текстом, открывает список и сбрасывает активную подсказку. Выбор вызывает `onChange(option.label)`, затем необязательный `onSelect(option)`, закрывает список и сохраняет фокус в поле. Очистка вызывает `onChange('')`, открывает подсказки для пустого запроса и возвращает фокус в поле. Внешний `inputRef` позволяет родителю вернуть фокус после сброса фильтров. Mount, фокус без выбора и внешнее обновление `value` сами по себе callback не вызывают.

Поле имеет `role=combobox`, `aria-autocomplete=list`, связанный `label`, `aria-expanded`, `aria-controls` открытого списка. Подсказки — `listbox` и `option`. Фокус остаётся в поле; `aria-activedescendant` существует только для открытой и реально существующей активной опции. После обычного открытия первая опция автоматически не выбирается. Активная опция отслеживается по стабильному `value`, а не только по позиции.

| Действие | Поведение |
| --- | --- |
| Фокус или щелчок по полю | Открывает подсказки, включая предложения для пустого запроса. |
| ArrowDown / ArrowUp | Открывает список и циклически перемещает активную опцию; первый ArrowDown начинает с первой, ArrowUp — с последней. |
| Enter | Выбирает активную опцию открытого списка. Без активной опции не подменяет стандартное поведение Enter родительской формы. |
| Escape | Закрывает открытый список, сохраняя запрос. |
| Tab / Shift+Tab | Закрывает список без выбора; продолжает нативный переход фокуса. |
| Home / End / ArrowLeft / ArrowRight | Сохраняет нативную работу текстового курсора. |
| Pointer | Наведение мышью меняет активную опцию; щелчок выбирает. Touch не использует hover как обязательный шаг. |
| Blur наружу или pointer вне компонента | Закрывает список. |

Во время IME composition, `isComposing` и события с `keyCode=229` управляющие клавиши не перехватываются. Подсказка `hint` связана с полем через `aria-describedby`. При пустом `options` показывается `emptyText` как невыбираемое сообщение `role=status`; фиктивная опция не добавляется. `disabled` блокирует поле и очистку и скрывает список. Асинхронных loading/error, `readOnly`, отключения отдельной опции и отдельного состояния validation error в текущем API нет.

Меню абсолютно позиционировано и не сдвигает соседний контент. Оно выбирает пространство сверху или снизу, ограничивает высоту 280 px и доступным местом, учитывает `visualViewport`, сдвигается в пределах окна и прокручивает активную опцию. Поле занимает не менее 48 px по высоте; очистка — цель 44 × 44 px. Нейтральная фокусная рамка рисуется внутрь общего поля и включает иконку и очистку; второго контура вокруг самого input нет. При Off/reduce отключён переход рамки. Широкие подсказки и подписи переносятся; точное поведение touch, zoom, экранной клавиатуры и screen reader подлежит браузерной приёмке.

В `DiscoveryLab` предложение показывает имя материала, `ID · категорию` и ready/planned. Выбор запланированного материала только уточняет запрос; он не открывает отсутствующий компонент. Фильтр ищет по имени, ID, категории, офферу, описаниям EN/RU/VI и aliases. Группы объединяются через AND, выбранные значения внутри access/availability — через OR, отдельные слова запроса — через AND. Поиск нормализует регистр и диакритику, включая вьетнамскую `đ`. Это поиск по текущей локальной выборке, без поискового сервера и ранжирования релевантности.

## 14 · SystemDurationControl: range + number

Источники: `prototype/src/foundations/SystemMotionControls.tsx`, `config-control-validation.ts`, `system-config-controls.css`.

```ts
interface SystemDurationControlProps {
  locale: 'en' | 'ru' | 'vi';
  value: number;
  onChange: (value: number) => void;
  disabled?: boolean; // default false
  readOnly?: boolean; // default false
  initialDraft?: string;
}
const MOTION_DURATION = { min: 0, max: 400, step: 20, default: 160 };
type DurationError = 'required' | 'number' | 'range' | 'step';
type DurationResult =
  | { value: number; error: null }
  | { value: null; error: DurationError };
function validateDurationDraft(draft: string): DurationResult;
```

Нативные range и number управляют одним применённым значением. Контракт входного `value`: конечное целое число 0–400 мс, кратное 20. Родитель хранит его и получает `onChange` только после валидного изменения. Текст number хранится отдельно как черновик, поэтому пустая строка, промежуточный ввод, 35 мс и значение вне диапазона не изменяют применённую конфигурацию, range, код или архив. Вывод `Applied / Применено` показывает применённое значение, а не невалидный черновик.

`validateDurationDraft` различает отсутствие значения, некорректное число, выход за диапазон и нарушение шага. Пробелы по краям разрешены; отрицательный ноль нормализуется в 0. После валидного blur черновик приводится к строке числа. `initialDraft` применяется только при создании экземпляра: на стенде он показывает исправляемый ошибочный пример `35` при отдельном применённом значении 160. Это не второй источник конфигурации A001. Внешнее изменение `value` синхронизирует поле; для явного сброса черновика к тому же значению родитель пересоздаёт экземпляр через `key`.

Range использует нативные стрелки, Home/End и установленный `step=20`; number сохраняет нативную клавиатуру редактирования и шаг изменения. Обработчики не вводят собственных глобальных сочетаний и не меняют фокус. Фокус видим нейтральным цветом. Range связан с видимым label, number имеет имя с единицами `ms`; оба ссылаются на область пояснения. Ошибка помечает number через `aria-invalid` и получает конкретный локализованный текст. Область обратной связи — `aria-live=polite`; все конечные варианты текста участвуют в одной CSS-grid ячейке, скрытые варианты исключены из доступного дерева и визуально невидимы. Это резервирует высоту подсказки и не двигает range при смене ошибки.

`disabled` блокирует оба нативных контрола. В режиме `readOnly` number доступен для чтения и выделения текста, но не изменения; range отключён, потому что нативного readonly-поведения у него нет, и имеет `aria-readonly`. Отдельной операции clear нет: пустой number — ошибка required, применённое значение сохраняется. Общего loading/server error у синхронного контрола нет. Минимальная высота range и number — 44 px; блок number имеет фиксированную ширину, цифры табличные. В узких состояниях образца layout меняется по медиазапросам, не по текущей цифре или ошибке. Сам range не анимирует геометрию; Off/reduce не изменяет значение.

Текущая область API — длительность в миллисекундах с конкретным диапазоном и шагом. Это не универсальный slider для произвольных единиц и не обещание одинакового поведения всех платформенных number-input. Для повторного использования с иными границами потребуется отдельное расширение контракта.

## 15 · SystemHexColorField / SystemColorControl

Источники: `prototype/src/foundations/SystemColorControl.tsx`, `config-control-validation.ts`, `system-config-controls-copy.ts`, `system-config-controls.css`.

```ts
interface SystemHexColorFieldProps {
  locale: 'en' | 'ru' | 'vi';
  value: string;
  onChange: (canonicalHex: string) => void;
  disabled?: boolean;
  readOnly?: boolean;
  initialDraft?: string;
}
interface SystemColorControlProps {
  locale: 'en' | 'ru' | 'vi';
  value: string;
  onChange: (canonicalHex: string) => void;
}
function normalizeHexColor(draft: string): string | null;
function previewColorContrast(value: string): {
  foreground: string;
  label: 'dark' | 'light';
  ratio: number;
  background: string;
  passes: boolean;
};
```

`SystemHexColorField` отделяет редактируемый черновик от применённого цвета. Приёмный формат — непрозрачный `#RGB` или `#RRGGBB`; пробелы по краям удаляются, короткая запись разворачивается, буквы приводятся к верхнему регистру. Alpha HEX, RGB/HSL, CSS-переменные и выражения не принимаются. Входной `value` родителя должен быть валидным непрозрачным HEX; в интеграции хранится канонический `#RRGGBB`.

Ввод изменяет только черновик. Кнопка Apply или Enter вызывает `onChange(canonicalHex)` после успешной проверки; невалидный черновик остаётся в поле и не попадает в компонент, промпт или файлы. Видимый swatch показывает применённый цвет. Пустое и некорректное значение получают разные подписи, `aria-invalid` и связанный `aria-describedby`. Все конечные тексты занимают одну grid-область обратной связи; смена ошибки не перестраивает поле. `initialDraft` используется только при mount для локального исправляемого образца `#EB`; это не применённая конфигурация. Применение и ввод не перемещают фокус принудительно.

`disabled` блокирует поле и Apply. `readOnly` сохраняет поле для чтения и выделения, убирает Apply и не вызывает `onChange`; Enter ничего не применяет. Нативная работа текстового курсора, Tab и активации кнопки сохраняется. Очистка поля не равна сбросу: пустой черновик не применяется. `SystemColorControl` добавляет сброс к утверждённому `#EBD183`, образец сочетания и расчёт контраста. Сброс также пересоздаёт поле, чтобы удалить невалидный черновик даже при уже применённом Saffron Lighter.

Расчёт сравнивает фон с `#101713`, затем `#FFFFFF`, затем `#000000`; выбирает первую из этих допустимых пар с необходимым контрастом. Результат показывает фактические HEX, численный коэффициент и подпись прохождения порога 4.5:1 для обычного текста. Цвет применяется только к A001 и его экспортируемой конфигурации; палитра самого сайта остаётся утверждённой. Это локальная проверка конкретной пары, не аудит всей темы, всех состояний компонента или доступности проекта.

Размер поля, swatch и Apply не меньше 44 px по высоте. На узкой ширине Apply и сброс занимают полный ряд; поля и описания переносятся. Фокус — нейтральная внутренняя рамка. Цвет не анимируется во времени, отдельной reduced-motion логики не требуется. В разделе состояний доступны отдельные invalid/disabled/readOnly экземпляры, не меняющие A001. Текущий API не включает графический цветовой picker, opacity, eyedropper, градиенты, сохраняемую библиотеку цветов и серверные ошибки.

## 18 · SystemFilterChip

Источники: `prototype/src/foundations/SystemFilterChip.tsx`, `system-filter-chip.css`; композиция фильтров и восстановление фокуса — `DiscoveryLab.tsx`.

```ts
interface SystemFilterChipProps {
  label: string;
  removeLabel: string;
  onRemove: () => void;
  disabled?: boolean;
  buttonRef?: React.Ref<HTMLButtonElement>;
}
type DiscoveryFilters = {
  query: string;
  category: 'all' | DiscoveryCategory;
  access: readonly ('free' | 'pro')[];
  availability: readonly ('ready' | 'planned')[];
};
function filterDiscoveryMaterials(
  materials: readonly DiscoveryMaterial[],
  filters: DiscoveryFilters,
): DiscoveryMaterial[];
```

Один chip — одна нативная кнопка удаления критерия. `label` виден целиком с переносом, `removeLabel` задаёт локализованное доступное имя действия с группой и значением, например «Убрать фильтр: Доступ — Бесплатно». Декоративный крестик не создаёт второй Tab-stop. Щелчок, Enter и Space вызывают `onRemove`; hover сам ничего не снимает. `disabled` использует нативное отключение кнопки. Readonly, error и loading не являются состояниями этого API; если критерий не должен удаляться, родитель не создаёт ложное действие.

Компонент не владеет списком критериев и не переносит фокус самостоятельно. В `DiscoveryLab` после удаления родитель фокусирует следующий chip, если он есть; иначе предыдущий; после последнего — видимый summary фильтров. `buttonRef` нужен для этого восстановления. Кнопка сброса всей выборки возвращает фокус в поиск. При отсутствии активных критериев показывается локализованный текст, а не пустая кнопка. Запрос имеет свою очистку в search, а не превращается в неявный chip.

Внутри групп access и availability действует OR: free + pro не даёт пустой результат, ready + planned включает оба состояния. Разные группы и category соединены через AND, затем применяются слова запроса. Функция возвращает новый массив и не меняет исходные материалы; сортировкой владеет родитель. Число результатов обновляется через `role=status`. Нулевой результат показывает отдельный empty state с доступным сбросом; planned не становится готовым из-за фильтра.

Минимальная цель chip — 44 px по высоте и ширине. Длинные подписи переносятся без растягивания страницы; группа переносится по доступной ширине. Focus нейтральный, удаление не зависит от цвета крестика. Анимаций в chip нет; Off/reduce не меняет семантику и действие. Сохранение критериев в URL/аккаунт, удалённые фасеты, количественные счётчики отдельных опций и произвольный серверный фильтр в текущую локальную реализацию не входят.

## 28 · SystemProgress / ProgressSpecimen

Источники: `prototype/src/foundations/SystemProgress.tsx`, `system-progress.css`, `ProgressSpecimen.tsx`, `progress-specimen.css`. Якорь образца — `#progress`.

```ts
interface SystemProgressProps {
  label: string;
  value?: number;
  max?: number; // default 100
  valueText?: string;
  hint?: string;
  indeterminate?: boolean; // default: value === undefined
  tone?: 'default' | 'success' | 'error'; // default default
  locale?: string;
}
function ProgressSpecimen(props: {
  locale: 'en' | 'ru' | 'vi';
  motionOff?: boolean;
}): React.ReactElement;
```

`SystemProgress` — отображение прогресса без побочных эффектов. Операцией, её обновлением, ошибкой и отменой управляет родитель; компонент не запускает таймер, загрузку, запрос или обещание завершения. Конечное положительное `max` задаёт предел, в остальных случаях используется 100. Значение ограничивается диапазоном 0…max; нечисловое или бесконечное значение отображается как 0. При отсутствии `value` по умолчанию включён indeterminate.

Полоса имеет `role=progressbar` и видимую связанную подпись, `aria-valuemin=0`, `aria-valuemax`; в определённом режиме передаёт ограниченное `aria-valuenow`, в неопределённом — не передаёт его. `hint` связан через `aria-describedby`; `valueText`, если задан, используется и как видимый текст, и как `aria-valuetext`. Иначе конечный процент форматируется через `Intl.NumberFormat(locale)`. Для indeterminate родитель передаёт содержательную подпись, например «Ожидание». `tone` меняет визуальный цвет, но не создаёт текст состояния: ошибка и завершение должны быть названы родителем. Произвольный `locale` должен поддерживаться `Intl.NumberFormat` среды.

Полоса не является интерактивным контролом, не получает Tab-stop и не имеет keyboard/disabled/readOnly API. Кнопку отмены или повтора размещает родитель; она должна отменять реальную операцию, если таковая существует. Empty state заменяется родителем, а не имитируется нулевой загрузкой. Отдельного `aria-live` на каждом числовом обновлении нет: это предотвращает непрерывное озвучивание каждого процента.

`ProgressSpecimen` показывает честный локальный сценарий: старт устанавливает 25%, «Следующий шаг» переводит на 70%, затем 100%; ошибка останавливает продвижение, повтор начинает с 25%; отмена блокирует следующий шаг до повтора; сброс возвращает 0 и исходное состояние. Во втором образце старт/стоп включает и прекращает неопределённое ожидание. Никаких файлов, фоновых задач и искусственного сетевого прогресса за этим нет. Действия озвучиваются единой polite live-областью. Конечные тексты состояния находятся в одной grid-ячейке, поэтому переключение между ними не меняет высоту.

Определённая полоса меняет заполнение без анимации числовых значений. Indeterminate двигает короткий сегмент; при системном reduce или глобальном Off сегмент остаётся неподвижным по центру, а текст сохраняет смысл. Полоса занимает доступную ширину; карточки образца складываются в одну колонку до 780 px, кнопки — в одну колонку на узком экране. Кнопки имеют минимальную цель 44 px. Forced colors оставляет различимыми фон и заполнение. Не реализованы круговой progress, многоэтапная очередь, пауза сетевой операции, вычисление ETA и привязка к upload/download API.

## 34 · SystemPreviewViewport

Источники: `prototype/src/foundations/SystemPreviewViewport.tsx`, `system-preview-viewport.css`; пример встраивания — demo-панель `SystemStudy.tsx` в `#workbench`.

```ts
type SystemPreviewWidth = 'full' | 'tablet' | 'mobile';
interface SystemPreviewViewportProps {
  locale: 'en' | 'ru' | 'vi';
  label: string;
  children: React.ReactNode;
  width: SystemPreviewWidth;
  onWidthChange: (width: SystemPreviewWidth) => void;
  motionOff?: boolean; // default false
  onReset?: () => void;
}
```

Шириной владеет родитель. Общий `SystemSegmentedControl` выбирает full, максимум 640 px или максимум 320 px и вызывает `onWidthChange`. Эти значения — верхние границы, а не принудительная минимальная ширина: при недостатке места iframe сужается до контейнера. Строка «Фактическая область» показывает измеренную ширину и зарезервированную высоту в CSS px. Смена режима не изменяет URL или исходники компонента сама по себе.

Пример рендерится React portal в отдельный фиксированный пустой `srcDoc` документ iframe. У него собственный viewport для media queries и отдельное дерево документа. При загрузке копируются уже авторские локальные style/link и встроенные шрифты, передаются вычисленные CSS custom properties и шрифт родителя; min-height страницы сбрасывается, чтобы не создавать петлю высоты от `100vh`. Родительские media queries внутри клонированного CSS вычисляются по ширине iframe, а не окна сайта.

`ResizeObserver` измеряет контент и iframe; загрузка шрифтов повторяет измерение. Базовый резерв — 440 px, затем высота может вырасти до содержимого без обрезки. Максимальный резерв хранится отдельно для языка, выбранного режима и фактической ширины, поэтому смена состояния в том же размере не уменьшает высоту, а возврат с узкого окна на широкое не наследует его резерв. Это механизм под размер контента, а не универсальное обещание нулевого layout shift для любого произвольного `children`: более высокий ранее не измеренный контент увеличит резерв.

«Сбросить превью» увеличивает внутренний ключ portal-поддерева и пересоздаёт сам пример, после чего вызывает необязательный `onReset`. Это реальный сброс внутреннего состояния A001; настройки родителя — цвет, язык, duration, выбранный target — сохраняются. Сброс не перезагружает весь сайт и не подменяет кнопку скриншотом.

Ширина управляется нативной radio-клавиатурой общего segmented; reset — нативная кнопка Enter/Space. Iframe получает доступное имя через обязательный `title={label}` и описание области просмотра. Фокус входит и выходит по нативному порядку Tab; нет ловушки, autofocus или отдельного перехвата Escape. Неактивная demo-панель имеет родительские `inert` и `aria-hidden`, а iframe не получает программного фокуса. Браузерное подтверждение исключения вложенных кнопок из AX и Tab-порядка записывается в общем отчёте, не выводится только из наличия атрибутов.

`motionOff` передаёт `data-motion=off` в документ примера и его корень. Геометрия iframe не анимируется; системный reduce продолжает работать через media query. Полоса настроек переносится, на узком экране reset стоит справа отдельным рядом. Disabled/readOnly/error/loading не представлены отдельными props: компонент показывает доверенный локальный материал и не создаёт фиктивный загрузочный запрос.

Граница безопасности конкретная: `sandbox="allow-same-origin"` без `allow-scripts`, forms, popups и downloads; в `srcDoc` не интерполируется пользовательский HTML и не добавляются script-узлы. Trusted React-обработчики выполняются родительским приложением. Это изоляция документа, стилей и размера доверенного локального примера. Это не готовая песочница для запуска чужого кода, не полноценный CSP-профиль продакшена и не механизм приёма произвольного HTML. Обновление родительских style/link после первоначальной загрузки не синхронизируется автоматически; отдельный экран ошибки iframe и мониторинг отказов в текущий API не входят.

## 35 · SystemMotionControls

Источники: `prototype/src/foundations/SystemMotionControls.tsx`, `config-control-validation.ts`, `system-config-controls-copy.ts`, `system-config-controls.css`; область стенда — `#roles`.

```ts
interface SystemMotionControlsProps {
  locale: 'en' | 'ru' | 'vi';
  duration: number;
  onDurationChange: (value: number) => void;
  profile: 'subtle' | 'expressive';
  onProfileChange: (value: 'subtle' | 'expressive') => void;
  forceOff: boolean;
  onForceOffChange: (value: boolean) => void;
  reduced: boolean;
  onReplay?: () => void;
}
function resolveMotionState(
  duration: number,
  forceOff: boolean,
  reduced: boolean,
): {
  reason: 'off' | 'reduced' | 'instant' | 'active';
  effectiveDuration: number;
  controlsDisabled: boolean;
};
```

Родитель хранит настроенную длительность, профиль `subtle | expressive` и пользовательский Off; значение системного reduce передаётся отдельно. Контракт duration совпадает с семейством 14: 0–400 мс с шагом 20. `resolveMotionState` проверяет его и выбрасывает `RangeError` при нарушении контракта; UI-черновик не отправляет такие значения наверх. Пользовательский Off, затем системный reduce имеют приоритет над duration. Эффективная длительность при любом из них — 0; иначе 0 мс именуется instant, положительная — active.

Профиль выбирается общим `SystemSegmentedControl` с нативной radio-семантикой и вызывает `onProfileChange`. В стенде он попадает в конфигурацию A001, код, промпт и архив, если движение включено. При Off/reduce выбор профиля, duration и быстрых значений недоступен; настроенные значения сохраняются для последующего включения. Checkbox показывает `forceOff || reduced`; при системном reduce он отключён, поэтому UI не предлагает отменить предпочтение ОС. Статус явно различает пользовательское отключение, системное уменьшение движения, мгновенную смену и заданную длительность. Он имеет `role=status`, `aria-live=polite`, `aria-atomic=true`; скрытые варианты текста сохраняют высоту и исключены из доступного дерева.

Быстрые значения duration задают 0, 120, 160 или 240 мс и применяются через `onDurationChange`; каждая из четырёх кнопок имеет `aria-pressed` по точному совпадению числа. Изменённое вручную значение между ними не отмечается как другое готовое значение. Эти кнопки не заменяют отдельный выбор характера `subtle | expressive`.

«Повторить» каждый раз запускает один проход локального маркера от начала к концу через Web Animations API и вызывает `onReplay`; в стенде callback пересоздаёт A001, сохраняя его настройки. Для subtle маркер проходит 16 px, для expressive — 38 px, за эффективную длительность и с фиксированным easing `cubic-bezier(.2,.8,.2,1)`. При повторном нажатии, смене настроек или размонтировании предыдущая анимация отменяется; проходы не накапливаются. При нулевой длительности или отсутствии `Element.animate` маркер сразу получает конечное положение. Это не запуск фоновой операции.

Reset отменяет текущую анимацию, возвращает duration=160, `profile='subtle'`, `forceOff=false`, исходный маркер и чистый числовой черновик; системный reduce остаётся действующим, поскольку родительское предпочтение ОС не изменяется.

Связанные range/number сохраняют клавиатуру и фокус семейства 14. Профиль использует нативные стрелки и Space radio-группы. Checkbox и кнопки используют нативные Tab/Space/Enter; действия не переносят фокус в соседние разделы. Disabled/readOnly/error представлены исправляемыми отдельными экземплярами duration в раскрываемом разделе; они не меняют A001. Сам `SystemMotionControls` не имеет общего `disabled` или `readOnly` prop. Empty state неприменим к конечному набору настроек; серверного error/loading нет.

Блок настроек и результат переходят из двух колонок в одну до 767 px. Нейтральная фокусная рамка не смешивается с selected. Длительность анимации маркера берётся из эффективного значения; при нуле он меняет положение сразу. Системный reduce и пользовательский Off не запускают Web Animations проход. Текущее API управляет профилем, длительностью и включением примера, не редактирует easing, timeline, scroll trigger или многокадровую анимацию и не сохраняет настройки в аккаунте.
