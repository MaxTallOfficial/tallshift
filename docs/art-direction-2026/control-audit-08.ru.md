# Tallshift UI / 08 — проверка контролов выбора

Это отчёт по трём существующим общим компонентам. Он фиксирует изменения кода и проверки разметки; не подтверждает полную готовность дизайн-системы, тестирование скринридером или прохождение всех браузеров.

## SystemSelect

Исправлено:

- Неизвестное контролируемое `value` больше не подменяется первым пунктом. Отображается тире; `onChange` самопроизвольно не вызывается.
- Активный пункт хранится по стабильному `value`. После удаления, перестановки или блокировки пунктов `aria-activedescendant` формируется только для существующего доступного пункта.
- В `SystemSelectOption` добавлен `disabled`. Такой пункт виден и объявлен `aria-disabled`, пропускается стрелками, Home/End и поиском по буквам; нажатие не меняет значение и не закрывает список.
- Для пустого списка trigger недоступен. Если все существующие пункты заблокированы, их можно просмотреть, но выбор невозможен.
- Повторение одной буквы переходит по подходящим доступным пунктам; сравнение игнорирует регистр и диакритику, включая вьетнамскую `đ`.
- Обработка клавиатуры не перехватывает IME-композицию (`isComposing` / код 229).
- Верхний popup привязан к контейнеру самого trigger, без фиксированной поправки на высоту label. Длинная подпись не сдвигает popup поверх контрола. Доступная высота учитывает visual viewport и не принуждается к 44px при отсутствии места.
- Изменение viewport / внешняя прокрутка закрывает popup; прокрутка списка оставляет его открытым. Обработчик resize проверяет, что target является Node, прежде чем вызывать `contains`.
- Добавлен опциональный `readOnly`: контрол остаётся в Tab-порядке, объявляет `aria-readonly`, сохраняет значение и не открывает список.
- Опциональный `hint` связан через `aria-describedby`. Disabled / активный пункт получили правила для forced colors.

Контракт: `value` управляет родитель. Значения `options[].value` должны быть уникальными. `disabled` блокирует весь trigger; `readOnly` разрешает фокус и чтение без изменения. Длинное выбранное значение обрезается визуально с `title`, полный текст остаётся в DOM; пункты списка переносятся. Компонент пока не поддерживает группы пунктов, multiple, асинхронную загрузку, произвольный placeholder или интеграцию скрытого native input с form submission.

## SystemSearchCombobox

- Добавлен опциональный `readOnly` на native input и `aria-readonly`. В этом режиме popup и кнопка очистки не предлагаются, текст доступен для выделения и копирования.
- Смена query извне сбрасывает прежнюю активную подсказку. Enter после внешней смены query не должен выбирать пункт, активированный для предыдущего текста.
- Сохранены native caret-клавиши Home/End/Left/Right, IME-защита, локальные подсказки родителя, unique values, popup с учётом visual viewport, 44px clear target, отсутствие автоматического выбора первой подсказки.

Контракт: это синхронный локальный поиск. Loading/server-error/API-search сюда не добавлены. `onChange` получает введённый текст; `onSelect` получает объект выбранной подсказки. Факт совпадения текста с label сам по себе не означает подтверждённый выбор.

## SystemSegmentedControl

- Сохранены native radio inputs с отдельным `name` на экземпляр, fieldset/legend, групповая и индивидуальная блокировка, горизонтальная/вертикальная раскладка.
- Добавлен опциональный `hint`, связанный с radiogroup через `aria-describedby`.
- Клавиши остаются native radio поведением браузера; это выбор настройки, а не tabs. Режим readOnly для radio не выдумывается: при необходимости запрета изменения используется `disabled` с объяснением рядом.

## Проверки

Добавлен `prototype/tests/control-semantics-08.test.ts`: четыре SSR-проверки реальных TSX-модулей. Проверяются неизвестное значение select, семантика readOnly/empty, отсутствие изменяющей кнопки у readOnly search, связи hint и независимые имена/уникальные ID двух segmented экземпляров. Все четыре прошли отдельно.

Это проверки серверной разметки, а не доказательство поведения клавиш, указателя, позиции popup или чтения assistive technology. TypeScript (`tsc -b`) прошёл после интеграции общих импортов. Итоговую сборку и браузерную проверку выполняет интегратор.

Для ручной проверки добавлен `ControlAuditSpecimen` (EN/RU/VI): свёрнутый по умолчанию раздел `#control-edge-states` с выбором / disabled option / длинным пунктом, readOnly select/search, неизвестным value, disabled select и segmented с отдельным недоступным пунктом.

Осталось проверить в браузере: стрелки / Enter / Escape / Tab, выбор указателем, изменение размера и прокрутка при открытом списке, 320px, popup вверх с длинным label, видимость фокуса, forced colors, реальные IME на macOS/Windows, VoiceOver / NVDA. Группы, async loading/error и form submission требуют отдельных API-решений и не считаются закрытыми этим аудитом.
