## 1. Что должно остаться узнаваемым

Сервис продаёт авторский интерфейсный материал и движение. Его собственная оболочка должна показывать качество исполнения: сильную композицию, ясную иерархию, точную реакцию и самостоятельный графический характер. Главный объект внимания — материал библиотеки; оболочка помогает увидеть, понять и перенести его в проект.

Продуктовое обещание, предложенное для визуальной системы: **«Выразительный интерфейс, который можно сделать своим»**. Главными объектами становятся настоящие материалы библиотеки. Выбранный материал сохраняет узнаваемость между preview, поддержанными настройками, кодом, промптом и инструкцией. Для настройки за пределами встроенных параметров промпт описывает задачу адаптации; интерфейс не имитирует выполненную работу AI.

У системы должен быть узнаваемый принцип композиции, формы и движения. Выразительность демонстрирует качество материала; рабочая область обеспечивает читаемый код, предсказуемое управление и ясный результат действия. Для выразительного сценария в handoff обязательны продаваемая ценность, реальный материал и наблюдаемое доказательство связи с ней. Декоративная форма сама по себе не доказывает ценность библиотеки.

Три ранее исследованных направления (выбрано Afterlight):

| Направление | Характер | Принцип формы | Грамматика движения | Главная проверка |
|---|---|---|---|---|
| **Material Signals** | Тёплый светлый, тактильный, атласный | Плотная поверхность, складка, срез, мягкое материальное освещение | Короткое давление, раскрытие плоскости, перенос света между состояниями | Сохраняет ли интерфейс точность инструмента, когда материал становится выразительным? |
| **Type Foundry** | Редакционный, геометричный, типографический | Сильная сетка, крупный набор, контраст масштаба, дисциплина линий | Сборка строки, смена оси, сдвиг по базовой линии, оконная маска | Работает ли характер с кириллицей и длинным русским текстом? |
| **Afterlight** | Тёмный минеральный инструмент | Глубокие непрозрачные поверхности, локальная подсветка, тонкая грань | Короткое проявление контура, перекрытие слоёв, точный пространственный ответ | Не страдают ли код, контраст и производительность от атмосферы? |

Material Signals и Type Foundry сохраняются как история исследования. Дальнейшая работа идёт в Afterlight на утверждённых Saffron Lighter и Manrope; композиция и компоненты проверяются на системном стенде.

## 2. Архитектура токенов

Три обязательных уровня: **primitive → semantic → component**.

- **Primitive:** сырые палитры, размерные ступени, гарнитуры, веса, оптические параметры, радиусы, длительности, кривые. Не использовать напрямую в продуктовых компонентах, кроме явно обозначенных графических объектов.
- **Semantic:** назначение в интерфейсе. Одинаковые имена во всех направлениях, даже когда конкретные значения различаются.
- **Component:** локальные решения семейства, ссылающиеся на semantic. Локальный токен нужен, если решение действительно повторяется или требуется независимая настройка; не создавать токен для каждой CSS-декларации.

```text
primitive.color.berry.600
    → semantic.action.primary.background
        → component.button.primary.background

primitive.color.neutral.950
    → semantic.content.onAccent
        → component.button.primary.foreground
```

Первый пример — структура ссылки, а не утверждённая палитра. Данные поставляются в JSON с типом, описанием и ссылкой-алиасом; CSS custom properties и типы для кода генерируются из одного источника. Источник, версия и статус утверждения видимы в репозитории. Циклические ссылки и неразрешённые алиасы запрещены.

### 2.1 Семантические цветовые роли

Обязательные группы:

| Группа | Минимальные роли |
|---|---|
| Поверхности | `canvas`, `surface`, `surfaceRaised`, `surfaceInset`, `surfaceInverse`, `scrim` |
| Контент | `contentPrimary`, `contentSecondary`, `contentMuted`, `contentInverse`, `contentOnAccent`, `contentOnStatus` |
| Действие | `actionPrimary` default/hover/pressed, `actionSecondary`, `actionQuiet`, `actionDisabled`, `link`, `linkVisited` |
| Выбор | `selectedBackground`, `selectedBorder`, `selectedForeground`, `selectionText` |
| Границы | `borderSubtle`, `borderControl`, `borderStrong`, `focusRing`, `focusGap` |
| Семантика | success/info/warning/error: background, border, icon, foreground |
| Спецобласти | `codeBackground`, `codeForeground`, syntax roles, preview checkerboard, media placeholder |

Брендовый акцент, success, error и focus — отдельные роли. Они могут оказаться близкими по оттенку только после проверки, но не должны быть одним связанным токеном. Обновление акцента не перекрашивает автоматически ошибку, синтаксис кода и статус покупки.

`contentOnAccent` выбирается по реальной заливке. Нельзя предполагать, что на любом насыщенном акценте нужен белый текст. Прозрачность учитывается после композиции с фоном. Выбранная палитра должна иметь проверенные пары для всех используемых состояний, а не один удачный пример кнопки.

### 2.2 Типографика EN/RU/VI

В текущем кандидате / 05 роли: display, H1, H2, H3, body, UI, meta; code и numeric задаются по назначению. Числовая шкала находится в `prototype/src/foundations/system-scale.ts` и handoff JSON. У каждой — family, size, weight, line-height, letter-spacing, optional width/optical-size. Display и рабочий текст могут использовать разные гарнитуры; третий шрифт допустим для кода. Количество загружаемых файлов и реальная цена в байтах входят в решение о выборе.

Для variable font обязательны: легальная лицензия для веба и self-hosting, полноценная кириллица и латиница, совместимые знаки валют, стрелки и нужная пунктуация; проверенные жирные начертания и fallback. Наличие файла variable не доказывает наличие кириллицы. Покрытие проверяется на фактически поставляемом файле. Текущий стенд использует локальный variable TTF Manrope; WOFF2 не заявляется.

Тестовый набор включает `ă â đ ê ô ơ ư ộ ợ ự ỹ`, NFC/NFD-ввод и строки: «Настроить анимацию», «Скопировать промпт», «Состояние операции», «Библиотека компонентов», `Create something considered`, `Adapt to my project`, `Next.js / Vite`, `0 O о О 1 l I`, `₫ $ € ₽`, `→ ↗ — – … «»`. Числа в ценах и метриках могут использовать tabular figures; основной текст не получает их автоматически.

Размеры и межстрочные интервалы утверждаются по образцам EN/RU/VI. Стартовые ограничения продукта: рабочий текст не уменьшать ради вмещения карточки; русские строки проверять с увеличением объёма на 40%; подписи не обрезать без доступа к полному значению; инструкции держать в удобной для чтения колонке. Для многострочного текста line-height должен допускать диакритику и кириллицу без обрезки. Трекинг крупного английского заголовка нельзя слепо переносить на русский.

Код — настоящий выделяемый текст, с переносом по выбору и горизонтальным скроллом только внутри собственной области. Табуляция, подсветка и номера строк не должны попадать в скопированный исходник, если не являются его частью.

### 2.3 Пространство, размер и плотность

Система использует компактную шкалу с базовой единицей и исключениями для оптического выравнивания. Кандидат / 05 использует 4, 8, 12, 16, 24, 32, 48, 64 px; шкала ещё согласовывается. Семантические интервалы: icon-gap, control-inline, control-stack, field-help, group-gap, panel-padding, card-padding, section-gap, page-gutter.

Три плотности: **comfortable** для каталога и touch, **standard** для рабочих панелей, **compact** только для дерева файлов и плотных метаданных. Плотность меняет внутренние отступы и интервалы, не скрывает действия и не делает touch-цели недоступными. Базовая высота рабочих контролов и ширина действий стабильны между default/pending/success/error.

Наш целевой touch-размер — 44×44 CSS px, даже если видимая иконка меньше. Это собственный проектный ориентир; минимальный критерий WCAG 2.2 AA — 24×24 с оговорёнными исключениями. См. [W3C: Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum).

### 2.4 Границы, радиусы, глубина и слои

Радиусы задаются ролями control/card/panel/overlay/pill/object. Pill не использовать повсюду; он должен означать конкретный тип компактного выбора или метки. У карточки и внутренней области согласуются вложенные радиусы и отступы.

Граница разделяет, тень показывает подъём, свет моделирует материал. Нельзя использовать одну размытую тень вместо всех трёх. У Afterlight слабая тень может заменяться гранью и контрастом поверхности. У Material Signals декоративный свет не изменяет читаемость контента. Type Foundry может опираться на линии и плотность набора.

Порядок слоёв фиксирован именами: base → sticky → floating → backdrop → modal → toast. Tooltip внутри modal принадлежит контексту этого modal. Никаких случайных `z-index: 99999`. Overlay не перекрывает системный focus и сообщения, необходимые для завершения действия. Popover позиционируется относительно окна и меняет сторону при нехватке места.

## 3. Общие состояния и взаимодействие

У каждого интерактивного семейства проверяются применимые состояния: default, hover, focus-visible, pressed, selected/current, disabled, pending, success, error, empty, loading. Отсутствующие состояния обозначаются как неприменимые, а не подменяются фиктивным UI.

- Hover — дополнительная реакция, вся функция доступна без него.
- Focus-visible — независимый видимый слой, не исчезающий на акцентной, тёмной и светлой подложке. Он не заменяется только изменением цвета текста.
- Disabled — элемент недоступен с понятной причиной рядом, когда причина нужна для следующего шага. Для ссылок и кнопок используются корректные семантические различия; нельзя рассчитывать только на opacity и `pointer-events`.
- Pending — действие действительно выполняется; размер и подпись не скачут. Не блокировать соседние независимые действия. Повторная отправка контролируется, отмена доступна, где операция её поддерживает.
- Success — только после фактического результата. Copy ждёт успешного Clipboard API; ошибка разрешений даёт понятное сообщение и доступный для ручного копирования текст.
- Error — сообщение описывает проблему и следующий шаг; введённые данные сохраняются. Сетевой отказ, неверный ввод и запрет доступа — разные случаи.
- Selected — не равно focus. После перемещения фокуса выбранное значение остаётся различимым.

Для асинхронных действий контракт задаёт источник результата, защиту от устаревшего ответа, поведение после unmount и при повторном запуске. Таймер сам по себе не означает успех. Демо симулированной ошибки явно подписывается; фиктивная покупка или download без файла не допускаются.

## 4. Доступность как часть формы

Цель — **WCAG 2.2 AA для продуктовой оболочки**, плюс собственное требование отключать несущественное движение. Это цель приёмки, не заявление о уже достигнутом соответствии.

Обычный текст проверяется на 4.5:1, крупный — 3:1; значимые границы и иконки требуют отдельной проверки нетекстового контраста. Пользовательский масштаб и настройки интервалов не должны разрушать функцию. Основные требования: [WCAG 2.2](https://www.w3.org/TR/WCAG22/) и [пояснение W3C о контрасте](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Клавиатурная последовательность следует порядку чтения. Нативная семантика предпочтительнее самодельной. Ссылки перемещают, кнопки выполняют действие. Для сложных виджетов используются узнаваемые клавиатурные модели и roving tabindex только внутри соответствующей группы. При смене маршрута — фокус на осмысленную точку нового контента, при фильтрации — сохранение фокуса в контроле. Focus не перекрывается sticky-панелью; см. [W3C: Focus Not Obscured](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/).

У формы есть постоянный label, подсказка, связь с ошибкой, понятное required и правильный input type/autocomplete. Placeholder не заменяет label. После submit с ошибками — summary и переход к первому полю по понятному действию. Не объявлять каждый ввод в live-region. Статус операции объявляется коротко, без дублирования toast и inline-статуса.

Альтернатива drag обязательна для функции, которую можно выполнить кнопкой или выбором. Диалог удерживает фокус только пока открыт; Escape и явное закрытие работают, предыдущий фокус восстанавливается. Не добавлять trap в обычную боковую панель на широком экране.

Проверять: клавиатуру, screen reader, zoom 200%, узкое окно 320 CSS px, увеличенный текст, forced colors, touch, reduced motion. Горизонтальный скролл допустим в code/media-viewport, но не из-за неуместившегося общего интерфейса.

## 6. Responsive-контракт

Брейкпоинты определяются переломами контента, не моделями телефонов. В кандидате / 05 границы сетки 768 и 1024 px, максимум контента 1240 px; числовые значения сохранены в `system-scale.ts` и handoff. Эти значения ещё согласовываются. Обязательные контрольные ширины для проверки: 320, 390, 768, 1024 и 1440 CSS px. Это тестовые размеры, а не пять обязательных breakpoint.

Компоненты реагируют сначала на доступную ширину своего контейнера. Перестановка панелей не меняет семантический порядок чтения. На узком экране settings открываются понятным действием; код сохраняет собственный скролл; вкладки не превращаются в пять неумещающихся кнопок. Touch и hover проверяются независимо от ширины.

Длинные названия, отсутствие изображения, пустой результат, 1/9/32 карточки, медленная загрузка и отказ сети входят в responsive-образцы. Декоративные объекты могут упрощаться; важные действия не исчезают. Не полагаться на фиксированную высоту браузера при открытой экранной клавиатуре.

## 7. Грамматика движения

У движения четыре роли: **response** (нажатие и результат), **relationship** (что изменилось и откуда), **orientation** (переход и фокус), **expression** (авторский характер). Каждая анимация должна иметь одну основную роль, явный trigger и конечное состояние.

Профили направления могут отличаться материалом и траекторией, но используют общие семантические motion-токены: feedback, state-change, panel, composition; enter/exit easing; travel XS/S/M; stagger budget. Числа утверждаются отдельно. Суммарный stagger считается частью продолжительности, а не скрытым дополнением. Рабочие действия не ждут завершения декоративного движения.

Повторение только по осознанному действию или с контролем pause. Продукт не перехватывает обычную прокрутку и не делает курсор обязательным интерфейсным инструментом. Указатель может слегка влиять на авторский объект, но не на hit area кнопки и не на чтение текста. Независимо от pointer сохраняются клавиатура, touch и статичная выразительная композиция.

Приоритет: **user Off → системный reduced motion → выбранный профиль**. Системное изменение учитывается без перезагрузки. При reduce убираются параллакс, масштабирование, длинные перемещения и циклы; состояние меняется сразу либо короткой неброской сменой непрозрачности, если она не ухудшает доступность. Контент не остаётся скрытым, ожидая intersection-анимации.

Автоматическое движение длительнее пяти секунд при одновременном другом контенте требует механизма остановки, если не действует исключение; см. [W3C: Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide). Отключение несущественной интерактивной анимации — собственное усиленное требование продукта; не выдавать его за отдельный обязательный критерий AA.

### Производительность

- Предпочитать transform/opacity для движения оболочки; изменение геометрии допускается осознанно, измеряется и имеет fallback.
- Не оставлять глобальный постоянный rAF-loop для декоративного эффекта. Observer, listeners, timers и WAAPI очищаются; неактивные и невидимые превью останавливаются.
- На одном экране приоритет получает активный материал. Сетка не запускает все тяжёлые демо одновременно.
- CSS/SVG — исходный вариант для оболочки. Canvas/WebGL добавляются только если дают существенный художественный результат, с отдельным бюджетом, статичным fallback и проверкой контекста GPU.
- Сохранять резерв геометрии: изображение, код и статус не вызывают ненужный layout shift. Локальная перегрузка не должна блокировать ввод и прокрутку.
- Бюджет байтов, результаты профилирования и тестовые устройства фиксируются для выбранной реализации. Нельзя объявлять «60 FPS» по визуальному впечатлению на одном компьютере.

Карточка motion-сценария в handoff: ID, цель, trigger, before/after, timeline, easing, расстояние, слои, конфликт с вводом, interruption/reverse, reduce/Off, touch, fallback, измеренная стоимость, видео или воспроизводимый пример.

## 9. Governance и передача в разработку

Источник истины — версия токенов и компонентов в репозитории, связанная с утверждённым визуальным артефактом. Финальное решение содержит выбранное направление, независимый акцент, гарнитуры с лицензиями, семантические пары и примеры их применения. Публичные экраны не получают промежуточную смесь разных кандидатов.

Для релиза системы требуются: changelog, перечень изменённых ролей и компонентов, статус доступности, responsive-образцы, motion-образцы, ограничения, миграция и ответственный reviewer. Ломающие изменения API/семантических токенов — major; добавления — minor; исправления без изменения контракта — patch. Изменение визуального поведения, влияющее на доступность, также явно описывается, даже если API тот же.

У компонента должны быть: анатомия и роль, props и ограничения, варианты и применимые состояния, примеры EN/RU/VI, размеры/плотности, токены и алиасы, keyboard model, accessibility notes, responsive behavior, motion contract, реальный пример и критерии проверки. Произвольные callbacks и пользовательский JSX не принимаются редактором настроек как JSON.

Definition of done для первого утверждённого набора: выбранная визуальная основа; согласованный акцент и on-accent; реальные файлы шрифтов; рабочие образцы ключевых семейств; полные состояния; keyboard/touch/reduce; проверка длинного текста и узкого окна; отсутствуют фиктивные действия; результаты проверок приложены. Полная production-библиотека из 44 семейств поставляется поэтапно, а не становится готовой автоматически после утверждения этого документа.

После этого можно переходить к подробной композиции экранов. До утверждения разумно совершенствовать style specimens и проверять качество системы на небольших фрагментах интерфейса, сохраняя текущий этап сфокусированным на характере, языке формы и поведении.
