# Tallshift UI /10 — оболочка, типографика и коммерческие композиции

Статус: общий React API подключён к стенду; визуальное утверждение, отдельные браузеры и ручная проверка скринридером не подменяются SSR-тестами.

## Оболочка и бренд

`SystemBrandMark` — именованная ссылка `href` (по умолчанию `#top`). `compact` оставляет компактный символ и полное доступное имя, `inverse` предназначен для поверхности акцента. Передавайте локализованный `aria-label` и реальную домашнюю ссылку. Полная надпись — `tallshift`; цветной знак декоративный.

`SystemNavigationShell` принимает `items: {id, href, label}[]`, `activeId`, `label`, `brand`, `edition`, `localeControl`, `skipLink: {href,label}`, `menuLabels: {open,close}`. Активная ссылка использует `aria-current="location"`. Семантика остаётся навигацией со ссылками, а не ARIA menu. Skip-ссылка должна указывать на существующий основной контент; обработку фокуса целевого раздела обеспечивает страница.

На ширине до 767 px ссылки скрыты обычным `display:none` до раскрытия. Кнопка имеет `aria-expanded` и `aria-controls`; после раскрытия Tab следует обычному DOM-порядку. Escape закрывает раскрытую навигацию и возвращает фокус кнопке. Выбор ссылки закрывает список. Это немодальная навигация без ловушки фокуса. На desktop ссылки всегда видны, кнопка скрыта. `mobileOpen/onMobileOpenChange` позволяют управлять раскрытием снаружи; без них компонент хранит состояние локально. При внешнем управлении родитель обязан обновлять значение.

`SystemLocaleControl` принимает `locale: en|ru|vi`, `onChange`, `label?`, `disabled?`. Это одна настройка на native radio, с полными самоназваниями языков и `lang` у вариантов. Компонент не перезагружает страницу, не сбрасывает пользовательские поля и не меняет локаль произвольного приложения сам: состояние, URL и `document.lang` сохраняет владелец страницы.

## Типографика

`SystemTypography` принимает `textRole: display|h1|h2|h3|body|ui|meta`, `as`, `numeric`, стандартные HTML-атрибуты. Видимый размер и уровень заголовка независимы: например, `as="h2" textRole="display"`. Размеры, вес и интерлиньяж берутся из единого `typographyScale`, на mobile используется мобильная шкала. `lang="vi"` отключает отрицательный трекинг, `numeric` включает табличные цифры. По умолчанию это параграф `body`; компонент не должен превращать всю прозу в однотипные UI-подписи. Существующие семантические заголовки и prose-стили остаются допустимы.

## Оффер

`SystemOffer` принимает типизированный `offer`: ID, имя, `availability: available|planned|closed`, бейдж, акцентный headline, описание, выгоды, явные `priceLabel/priceNote/deliveryNote`. Также есть `illustration`, `details`, `children`, `action: {label,onAction?,disabled?,reason?}`. Статус planned/closed всегда блокирует действие, даже при ошибочно переданном callback. Для available callback обязателен для включения кнопки. Цена не высчитывается из планового fixture и не выдаётся автоматически за действующее предложение.

Состав Product по-прежнему берётся из `accessProductOffer`: шесть ID, готовность planned, цена $29 — гипотеза до налогов. Активного checkout нет. A001 — единственный материал с рабочими исходниками. Контент и платёжная готовность не меняются от выделения общего компонента.

## Состояния доступа

`SystemEntitlementState` принимает `state: {kind,itemLabel,status,title,body,action,simulationLabel?}`, `active`, `announce`. `kind`: free/no-access/pending/owner/error/closed. Только free/owner с callback и без disabled могут включить действие. Для planned Product в owner-сценарии передаётся disabled: наличие демонстрации владельца не означает наличие файлов.

Это **представление**, не защита доступа. Сервер обязан повторно проверить права и доступность конкретного файла; клиентский компонент нельзя использовать как источник авторизации. Ошибка проверки не означает отсутствия покупки, поэтому error не превращается в приглашение оплатить повторно.

Для переключаемого стенда все состояния остаются в одной grid-ячейке: неактивные получают inert и aria-hidden, сохраняя резерв высоты. `announce` включается явно; статусный контейнер один, без дополнительного вложенного aria-live. На обычной статичной странице опция выключена по умолчанию.

## Проверка

`shell-offer-semantics-10.test.ts` проверяет SSR-семантику и связи ID: именованный бренд, текущую ссылку и skip, disclosure, локали, отделение роли шрифта от HTML-заголовка, блокировку плановых офферов, недопустимых состояний доступа, отсутствие callback и скрытые состояния. Тесты не проверяют фактическое перемещение фокуса, экранную раскладку или произношение скринридера; эти проверки фиксируются отдельно при общей интеграции.
