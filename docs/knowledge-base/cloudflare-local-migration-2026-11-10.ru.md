# Cloudflare и авторизация: локальная интеграция, 10.11.2026

Реализована локальная подготовка существующего Tallshift к Workers. Страницы, дизайн-система и версии Next 16.4.2 / React 19.3.1 / TypeScript 7 сохранены. Добавлены OpenNext 1.20.15, Wrangler 4.158.0, локальный конфиг и отдельные шаблоны staging/production. Реальных идентификаторов баз и секретов в них нет. OpenNext собирает приложение через build:web. Обработка Node proxy остаётся экспериментальной возможностью адаптера: локальные проверки прошли, но вопрос поддержки перед production остаётся открытым. CSP не ослаблялась.

Авторизация использует Better Auth 1.7.18 и Drizzle. Сессии проверяются через primary D1; opaque-токены хранятся в базе как SHA-256. Cookie — __Host, Secure, HttpOnly, SameSite=Lax. Политика: 30 дней абсолютного срока и 7 дней бездействия. CSRF связан с текущей сессией и точным Origin. Лимиты запросов используют атомарные счётчики D1. Одноразовый токен восстановления, смена пароля и отзыв сессий выполняются атомарно. Общие ограничения пароля 15–128 вынесены в shared-модуль.

Подключены /api/auth и пять экранов EN/RU/VI. В кабинете есть проверка сессии и выход с текущего или всех устройств. Избранное остаётся в браузере. Письма локализованы, URL строится из доверенного origin, токены и пароли не пишутся в логи. Без настроенной доставки регистрация и запрос восстановления закрыты; существующий вход и уже выданные токены не зависят от доступности отправителя. AUTH_LOCAL_MAIL пока зарезервирована и не реализует почтовую доставку.

## Проверки

- Полный Node suite: 260/260. После дополнительной проверки неподтверждённого email — focused auth 5/5. TypeScript проходит.
- Финальная OpenNext-сборка проходит. Настоящий local workerd проверен на EN/RU/VI: статика, разные nonce между ответами, nonce на скриптах и защитные заголовки.
- Хеширование и проверка правильного/неправильного пароля Better Auth выполнены в workerd. Локальное время — 262 мс; это не измерение CPU или нагрузки production-плана.
- Миграции 0001 TON и 0002 auth применены к локальной D1. Remote D1 не затронута.
- npm audit: 0 уязвимостей в реестре на момент проверки этого lockfile. Это не гарантия отсутствия дефектов безопасности.
- Браузер: 45 сочетаний экрана/языка/ширины, 5 проверок доступности при отключённой почте и 6 проверок кабинета/выхода. HTTP-ответы авторизации в этих проверках подменены синтетическими fixtures; это не настоящий браузерный вход или доставка писем. Сохранены 12 скриншотов, визуально просмотрены два представительных экрана. Проверены геометрия, ошибка входа, удаление токена из URL и состояние выхода.
- Защищённый Hallmark для product: 23 файла, 0 FAIL / REFLEX / WARN. Прежние 56 FAIL recipes относятся к открытому этапу упаковки CSS Modules и этой проверкой не закрыты.

## Границы готовности

Production-авторизация не включена. Нужны реальные D1 bindings, секреты, HTTPS-origin и отправитель писем; затем проверки доставки, сквозного сценария, устройств, нагрузки и восстановления. Решение по поддержке Node proxy нужно подтвердить до деплоя. Пользовательское утверждение, native VI и screen-reader audit не заявлены.

Продажи остаются выключенными. Серверные quotes, налоги и условия, история реальных заказов/grants, FX, публичные платёжные маршруты, cron/backfill, fulfillment и приватная выдача платных файлов ещё не подключены. Бесплатные скачивания не требуют аккаунта. [Передача TON-модуля](ton-payments-handoff-2026-11-07.ru.md) сохраняет эти ограничения.

Агенты остановились по лимиту использования; основной агент завершил локальную интеграцию и проверки. По запросу Max Tall от 10.11 подготовлен один коммит и push накопленных изменений после 4d33603. Фактический результат публикации проверять по Git. GitHub Actions вручную, облачные ресурсы, remote-миграции и деплой не запускались.
