## Правила, которые остаются для следующих примеров

1. **Скачанный комплект выглядит как демо.** Внутри Tallshift пример получает цвета из `--f-*` хоста, у пользователя — значения по умолчанию из блока токенов модуля. Значение по умолчанию обязано совпадать с утверждённым значением той роли `--f-*`, которую оно заменяет (`getSaffronTheme('light')`). 26.11 расходились: поверхность S001/S002/S003 (`#1E1D19` вместо `#161512`), кольцо фокуса E001/A003/A006/C001/C002 (`#F7EBCB` или акцент вместо `#B8B8B2`), текст кнопки C001 (`#17150F`, не из палитры). Исправлено; правило закреплено тестом `tests/hallmark-token-blocks.test.ts`.
2. **Hallmark и CSS Modules.** CSS Modules запрещают голый `:root`, поэтому значения по умолчанию лежат в блоке `:root .<корень> { --x-default-y: #… }`. Закреплённый Hallmark 2.0.0 такие блоки не распознаёт и даёт FAIL правила 48 на каждое объявление. Floor-правило не снимается waiver. Решение — `npm run check:design:recipes`: запускает неизменённую защищённую обёртку, печатает её сырой отчёт и строго проверяет только этот вид находок (селектор, только custom properties, точное значение, использование в модуле, совпадение с ролью `--f-*` или палитрой). Всё остальное остаётся FAIL. Сырые цифры checker всегда указывать в отчётах рядом с разбором; называть сырые FAIL исправленными нельзя.
3. **Ссылки внутри демо.** Обычный `#якорь` в демо ненадёжен: в локальном превью есть `<base href>` и якорь перезагружает iframe страницей сайта, на демо-сервере hash занят каналом связи и прокрутка не видна. Демо обрабатывает клик само: `preventDefault`, фокус на цель с `tabIndex={-1}`, `scrollIntoView({ block: 'nearest' })` — как в E001, C001 и теперь S001. В собственном сайте пользователя обработчик не нужен; это сказано в инструкции.
4. **Пороги container queries проверяются на реальных ширинах превью**: «По ширине» на 1440 px ≈ 880–896 px, «Планшет» 640 px (содержимое секции 576 px), страница 768 px ≈ 716 px. Порог, который не срабатывает ни на одной из них, прячет главную функцию примера (так было с двумя колонками S001 при 960 px; теперь 720 px).
5. **Сетка без «сирот».** S002 выбирает число колонок по числу карточек (`data-count`): 3 — одна, затем сразу три; 4 — 2 × 2; 5–6 — две, затем три. Остаток 2 + 2 + 1 у пяти карточек на средней ширине честно описан в инструкции.
6. **Одно публичное имя.** `displayName` рецепта (первая строка запроса для ИИ) и заголовки инструкций совпадают с названием страницы (`materialDisplayName`) на трёх языках. Закреплено `tests/example-public-names.test.ts`.
7. **Общие строки страницы примера** не должны говорить о конкретном примере: «код кнопки» в помощи запроса для ИИ и в названии условий использования показывался у всех примеров; исправлено на общие формулировки. Английский — US «color».

## Выдача бесплатных комплектов

Неизменяемого публикатора и реестра бесплатных релизов нет. ZIP собирается в браузере из исходников, встроенных в JS развёрнутой версии; manifest честно пишет `releaseStatus: local-prototype`, `itemVersion: 0.1.0-prototype`. Эндпоинта `/assets/free/{id}/{version}/{digest}.zip` из ТЗ v0.2 и серверного реестра Free нет; `publishedPaidReleases` пуст. Производственные «ворота» выдачи — только проверка настроек на странице (цвет, длительность) и список доступных примеров.

ZIP детерминирован для одинаковых настроек, поэтому его можно сверить с ожидаемым SHA-256. `scripts/verify-free-delivery.mjs` строит ожидаемые архивы из исходников и нажимает настоящую кнопку скачивания на сайте во временном Chrome (разрешён только адрес сайта, загрузки запрещены, байты читаются из Blob). 26.11 до изменений этой ветки: tallshift.com и preview.tallshift.com — по 36 из 36 совпадений (9 примеров × RU/EN/VI Next + EN Vite). Ветка меняет CSS и тексты, поэтому после её развёртывания сверку нужно повторить; до развёртывания живые ZIP остаются прежними и с новыми ожидаемыми хешами не совпадут.

## Как проверять

- `npm run check:design:recipes` из `prototype` — Hallmark по рецептам с проектным разбором; `npm run check:design` — страницы продукта.
- `HALLMARK_PUPPETEER=<папка с puppeteer-core> node scripts/verify-free-examples.mjs` при запущенном `npm run dev` (4173) — четыре примера: 320/768/1440, RU/EN/VI, поведение, клавиатура, reduced motion, forced colors, мобильные настройки, совпадение демо, кода, запроса для ИИ, инструкции, ссылки с настройками и ZIP (SHA-256 против того же рецепта в Node).
- `HALLMARK_PUPPETEER=… node scripts/verify-free-delivery.mjs https://tallshift.com` — сверка живых ZIP; `--expected-only` — только ожидаемые хеши.
- `HALLMARK_PUPPETEER=… node scripts/verify-example-labels.mjs` при запущенном стенде — подписи кнопок и заголовки всех готовых примеров: без разрыва слов по слогам; подписи и заголовки интерфейса — не больше двух строк (крупные заголовки демо от 24 px — по решению Max Tall от 27.11, только разрыв по слогам). Охват: страницы 320–1440 и ширины превью 640/320. Измерение взято из проверки A001 (BETA-19). Число строк крупных заголовков скрипт выводит отдельно. Менять правило — только с «да» Max Tall.
- Доказательства прогонов (снимки, JSON, логи) — только в `prototype/.qa/` (игнорируется Git, критерии v2). Скрипты пишут туда по умолчанию; в репозиторий — не больше 2–3 ключевых снимков на отчёт. Классификатор `check:design:recipes` меняется только с отдельного «да» Max Tall.
- Временная зависимость браузерных проверок: `puppeteer-core@24.43.1`, установленный без сети из локального кэша npm во временную папку (`npm install --offline --ignore-scripts`). Прежняя папка `/tmp/tallshift-hallmark-runtime` очищена системой.
