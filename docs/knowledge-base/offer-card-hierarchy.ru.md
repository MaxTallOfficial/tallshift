# KB-UI-002 · Иерархия карточки предложения

25 октября 2026. Переработка по замечанию Max Tall: крупная декоративная иконка рядом с маленьким названием создаёт конкурирующие акценты и пустое пространство.

Порядок чтения: результат для пользователя → краткое объяснение → конкретный состав → действие/статус продажи. Название набора и доступ — компактные метаданные в одной верхней строке. Заголовок оффера крупнее названия набора: 28/20 px на десктопе, 24/20 px на телефоне. Акцентным цветом выделяется смысловая часть оффера.

Верхняя строка отделена тонкой линией. Состав сгруппирован в строки, без крупных декоративных иконок. Состояние «в плане» и отсутствие продажи остаются явно обозначены. Нельзя визуально представлять запланированный набор готовым продуктом.

В SystemOffer сохранён необязательный illustration slot для совместимости; он ограничен 24 px в верхней строке. В текущих карточках State Relay/Product иллюстрации не используются. Для будущих карточек приоритет отдаётся реальному превью, если оно помогает понять предложение.

Реализация проверена на EN/RU/VI при ширине 320 px без горизонтального переполнения. Вариант остаётся на визуальном рассмотрении.

## Тарифная витрина

После проработки продаж витрина показывает Starter / Product / All packs. Product выделяется рамкой, ценой и редакционной пометкой «Для запуска продукта»; не использовать выдуманную популярность. На широкой сетке одинаковый порядок сравнения: имя и доступ, цена с разовостью и статусом гипотезы, задача, состав, действие. На узких экранах сохраняется порядок DOM.
