## 1. Решения и границы

**Подтверждено пользователем:**

- Публичный сервис для разработчиков и вайбкодеров.
- Готовый код и промпт адаптации к существующему проекту.
- React + TypeScript с поддержкой Next.js и Vite.
- Русский и английский с первого публичного запуска.
- Необходимы подробные требования к продукту, дизайну, вёрстке, контенту, ИБ и точный Free/Pro ассортимент. Коммерческую модель нужно сравнить и предложить.

**Рекомендованная база команды:** 24 самостоятельных элемента, 6 Free/18 Pro; три тематических платных набора; локальная настройка и экспорт; React/CSS Modules; Next App Router как первый вариант Next.js; спокойная светлая оболочка и выразительные коллекции; разовые покупки вместо запуска сложной подписки. Это предложения команды, а не дополнительные решения пользователя.

Рабочее обещание: **«Настрой выразительную секцию. Забери код и инструкцию для своего AI. Встрой в свой проект».**

Сайт не становится runtime-зависимостью проекта пользователя. Свой LLM, генерация из скриншота, UGC, marketplace, нативный мобильный UI, full dashboard kit и свободный page builder не входят в v1.

## 2. Что изучила команда

Четыре AI-агента покрыли продукт/рынок/монетизацию/каталог; UX/UI и адаптивную вёрстку; архитектуру/QA; ИБ/приватность. Во втором раунде проведены контентный review и перекрёстная проверка контрактов. Состав реальной команды реализации и ответственность — в [delivery-and-operations](spec-v0.2/delivery-and-operations.ru.md).

Использовались официальные страницы конкурентов и первичная документация стандартов/технологий. Исследование показало, что copy code, prompts, адаптация оформления и наборы уже представлены на рынке. Наличие этих функций не является доказанной уникальностью. Следует проверять полезность авторских работ и качество конкретного переноса.

Исследования с пользователями, покупки материалов конкурентов, внедрение их исходников, тестирование нашего приложения и сканирование ИБ не проводились. В документах отделены факты источников, проектные рекомендации и будущие критерии проверки.

## 4. Устройство продукта

Пользовательский путь: **каталог → демо → настройки → ручной код / комплект для AI → внедрение → проверка результата**.

Два самостоятельных сценария получения: разработчик скачивает файлы и подключает пример; пользователь с AI получает те же файлы и точную инструкцию агенту. Промпт не заменяет исходник неопределённым описанием. Поддерживаются режимы Preserve design и Adapt to project; второй использует соглашения/токены проекта с возможным изменением внешнего вида.

Внутри платформы двенадцать законченных модулей: каталог/поиск; Studio; preview runtime; source/ZIP exporter; prompt composer; коллекции; docs/локализация; local favorites/share; аккаунт/покупки; commerce/grants; registry/release pipeline; operations/support. Это функциональные части одного сервиса, а не двенадцать платных продуктов.

Качество Free и Pro одинаковое: полноценные файлы, обе среды, RU/EN, доступность, touch и reduced motion. Оплачивается состав авторских работ. Free не требует регистрации.

## 6. Дизайн сервиса и вёрстка

Дизайн оболочки и дизайн контента разделены. Платформа — нейтральная светлая инструментальная UI: крупные постеры, графитовый текст, синий акцент, короткая навигация. Коллекции Product, Editorial и Playful различаются типографикой, композицией, декоративными приёмами и движением. Смена коллекции не меняет управляющие кнопки Studio.

Предложены Inter с кириллицей и self-hosted WOFF2, tokens с рассчитанными контрастами, responsive grid от 320 CSS px. В Studio desktop — рабочая область и панель 320px; mobile — четыре сохраняющих состояние режима: Демо, Настройки, Код, Для AI. Исходники имеют собственный scroll; страница не должна переполняться горизонтально. Макеты и state gallery ещё предстоит сделать по подробному дизайн-приложению.

Маршруты `/ru/...` и `/en/...`, одинаковые ASCII slug. `/` — языковой выбор без принудительного геоперенаправления. RU/EN включает ошибки, подписи доступности, примеры, документы, prompts, support и коммерческие условия. Пользовательский текст не стирается при смене языка. Валюта и доступность оплаты не определяются языком.

Основные состояния обязательны: loading, empty, no results, offline, invalid config, clipboard failure, demo error, locked, проверка прав, pending payment, failed/refunded payment, истёкшая сессия, неподдерживаемая/отозванная версия. Пустой spinner не заменяет объяснение и следующий шаг.

## 7. Контракт кода, демо и настроек

Один авторский исходник и immutable release связывают демо, просмотр файлов, prompt и ZIP. Studio принимает только allowlisted JSON-данные. React API с callbacks/children/ReactNode существует отдельно от JSON-настроек. Собственные медиа подключаются интегратором в локальном проекте; публичная Studio выбирает только включённые media presets.

CI собирает базовые комплекты из Git; браузер создаёт итоговые config, target-specific Example, инструкции и ZIP из выбранного состояния. Обработка пользовательского текста не требует передачи на сервер. Разрешённый Pro base bundle сначала получается после проверки прав. Конкретный формат итогового архива — в engineering; schema/manifest/checksums и RU/EN docs обязательны.

Повторный экспорт одинакового состояния должен воспроизводить результат. Старые ссылки закрепляют версию и схему. Системный reduced motion приоритетнее Expressive. Декоративные циклы E003/S012 имеют доступный Pause/Resume и в экспортируемом компоненте.

Default share содержит оформление/движение; тексты и ссылки включаются только явным opt-in с пояснением публичности. Контекст проекта в share не попадает никогда. Полный ZIP и prompt содержат текущие валидированные настройки независимо от проекции share.

## 8. ИБ, данные и доверенные границы

Preview работает на отдельном registrable domain/site, без cookies аккаунта. Iframe имеет минимальные разрешения; bridge проверяет точные origin, source, channel и schema. Публично исполняемые демо-байты не считаются защищаемой тайной. Защищаются исходные комплекты, аккаунты, покупки и административный выпуск.

Pro выдача идёт через backend с проверкой пользователя и покрытия конкретного release при каждом запросе; private storage и no-store исключают общий cache. Hosted checkout получает серверную сумму; права возникают после проверенного webhook/сверки, не из return URL. Повторы, перестановка событий, overlap grants, refund и отзыв версии имеют отдельные сценарии приёмки.

В бете нет аккаунтов/БД/платежей. В v1 нет пользовательских uploads, произвольного JS/SVG, remote source loading, AI API и доступа сервиса к репозиториям. Контекст AI живёт только локально. ИБ-приложение задаёт сроки хранения, удаление, backups, восстановление и реагирование; это будущие проверки, не пройденный аудит.

## 9. Коммерческая рекомендация

Сначала бесплатная бета шести элементов. Затем три разовых набора и bundle. Центральная цена для теста: **$29 за набор, $59 за bundle**, без утверждения валюты/налогов до выбора продавца. Это гипотезы, не опубликованный прайс.

Покупка фиксирует item IDs и версию оффера; функциональные обновления этих IDs предлагается включать на 12 месяцев без автосписания. Новые items/наборы не включаются автоматически. Безопасные ранее покрытые версии можно повторно получать после окна, пока работает сервис; скачанный код не зависит от активной подписки. Security remediation поддерживаемых веток не требует продления функционального окна.

Цены, срок поддержки, личное/командное использование, клиентская передача исходников и последствия возврата должны стать согласованными условиями до продаж. Страна продавца и провайдер пока неизвестны. Это блокирует включение оплаты, но не завершение анализа, дизайн или бесплатный выпуск.
