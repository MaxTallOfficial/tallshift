## 2. Команда анализа и команда реализации

Текущий анализ выполнен четырьмя AI-агентами в двух раундах: продукт/рынок/каталог/сведение; UX/UI и вёрстка с повторным контентным review; архитектура/QA с перекрёстной проверкой; ИБ/приватность с проверкой границ. Это роли анализа в этом чате, не нанятые сотрудники и не проведённые исследования пользователей.

Рекомендуемые роли реальной реализации:

| Роль | Ответственность | Что должна подтвердить |
| --- | --- | --- |
| Product owner | Scope, цены, рынок, правила доступа, приоритеты | Состав оффера и ресурсные обязательства |
| Product designer | Оболочка, user flows, состояния, responsive, RU/EN layout | Прототип критического пути и спецификации состояний |
| Motion/content designer | Оригинальность коллекций, композиции и движение | Авторские материалы, motion fallback, provenance |
| Frontend/content engineer | React элементы, Studio, CSS, экспорт | Два host-проекта, code/demo equality, переносимость |
| Fullstack/platform engineer | Auth, commerce, private delivery, данные | Права, платежи, безопасный выпуск и миграции |
| QA/accessibility | Проверки интеграции, keyboard/AT/mobile, regression | Свидетельства прохождения acceptance, дефекты и риски |
| AppSec/Ops | Threat model, review, CI, production, восстановление | Security gates, restore rehearsal, runbooks |
| RU/EN technical editor | Интерфейс, docs, demo text, prompts и условия | Полнота переводов, терминология, совпадение смысла |

Роли можно совмещать. Для планирования нужны реальные доступные часы; восемь названий ролей не означают восемь полных ставок. Автор критичного изменения не должен быть единственным человеком, подтверждающим его приёмку. Для массового контента за каждым item закрепляются автор, reviewer и QA owner.

## 3. Дизайн и вёрстка как отдельные результаты

До массовой реализации дизайнер готовит: главную, каталог, один studio, collection, pricing, покупку/восстановление, docs и state gallery; mobile/tablet/desktop, RU/EN и длинные тексты. Интерактивные состояния значат больше, чем наличие одного красивого desktop-кадра.

Вёрстка проходит отдельный review: сетка, min/max ширины, focus, текстовый zoom, контраст, skeleton/CLS, границы собственного scroll, читабельность кода и работа iframe. Диапазоны и токены приведены в [design-and-layout.ru.md](design-and-layout.ru.md). Pixel-perfect сравнение допустимо с утверждённым макетом и фиксированными шрифтами/данными, а не с произвольным моментом анимации.

## 5. Как оценивать сроки и бюджет

Разделять три потока: платформа, производство элементов, коммерция/эксплуатация. Диапазоны инженерного приложения — предварительные person-days, а не календарь. Дизайн, ручная QA, переводы, support и исправления не исчезают при использовании AI.

Первый измеряемый этап — один сквозной элемент, а затем шесть Free. Записывать фактическое время авторской композиции, кода, перевода, review и возвратов. После первых трёх элементов пересчитать оставшийся каталог; отдельно учитывать сложность gallery/dialog, callbacks, длинных текстов и коллекционных медиа.

Календарный план строится по доступной загрузке людей и зависимостям B01–24. Параллельная разработка 18 Pro до проверки exporter увеличивает риск массовой переделки. Не привязывать дату платного запуска к числу законченных постеров.

## 6. Локализация с первого дня

Обязательны RU/EN: оболочка, ошибки, alt/aria labels, демо-контент, документация, source comments при необходимости, промпты, транзакционные письма, условия, support instructions. Код и ID общие; locale не определяет страну, валюту или право доступа.

| Понятие | RU | EN |
| --- | --- | --- |
| Тип контента | Секция / Компонент / Эффект | Section / Component / Effect |
| Группировка | Коллекция | Collection |
| Товар | Набор / Все наборы запуска | Pack / Launch Bundle |
| Получение | Забрать код / Скачать ZIP | Get code / Download ZIP |
| Агентный путь | Для AI / Сохранить дизайн / Подстроить под проект | For AI / Preserve design / Adapt to project |
| Движение | Без движения / Мягко / Выразительно | Off / Subtle / Expressive |
| Платёжный статус | Проверяем оплату | Confirming payment |
| Право на обновления | Обновления до {date} | Updates through {date} |

Смена интерфейсного locale сохраняет собственные тексты и выбранный кодовый target. Для замены demo copy есть отдельное действие. Pseudolocalization +40%, длинные email/URL и формат чисел/дат проверяются в release review. Если один перевод не готов, новый item не публикуется на половину каталога. Правки обеих локалей входят в новую content release, а не перезаписывают проданный архив.

## 7. Аналитика и пользовательские исследования

Начальные продуктовые события: `item_open`, `preview_start`, `config_changed`, `copy_success`, `bundle_download`, `integration_feedback`. У каждого есть allowlisted `item_id`, `item_version`, `locale`, `target`, `mode` где применимо; `config_changed` содержит только имя группы параметров, без значений. Для беты допустим запуск без необязательной аналитики. `checkout_started` и `order_confirmed` относятся к серверному commerce ledger, а не к общей frontend-аналитике.

`order_confirmed` создаёт сервер после проверки провайдера; `copy_success` — только при успешной операции. Логи не получают пользовательские тексты, URL fragment, project paths, emails, полные payment payloads и contents clipboard. Отчёт учитывает размер выборки и исключает тесты/администраторов.

План интервью и 12 интеграций описан в коммерческой части. UX-эксперименты не суммируются механически в ещё десятки обязательных интервью: сначала согласовать единый исследовательский план и использовать наблюдения разных специалистов в одной сессии. Результаты сохраняются в обезличенном виде с согласованным сроком хранения.

## 8. Критерии начала бесплатной беты

- Все шесть Free реализованы, не только занесены в JSON; каждый доступен без аккаунта с полным кодом/ZIP/промптом.
- RU/EN и обе среды подтверждены; source/demo/export совпадают.
- Нет дефектов, блокирующих содержимое, клавиатуру, touch или reduced motion; проверена замена локальных ресурсов.
- Preview изолирован; ни пользовательский контекст, ни приватные ключи не попадают в запросы/логи.
- Пройден сценарий ошибки preview/clipboard/storage/offline; условия бесплатного использования понятны.
- Указан канал обратной связи; security notice и процедура отзыва версии подготовлены.

12 наблюдаемых интеграций проводятся на этом выпуске. Успешность эксперимента определяет переход к масштабированию, а не право показать бета-версию участникам.

## 9. Критерии платного запуска

- Выполнены требования беты и результаты 12 пробных интеграций; критичные дефекты устранены.
- 24 уникальных элемента готовы, у каждого есть evidence и RU/EN, а три Pro набора содержат оригинальные материалы.
- Цена/валюта/продавец/оферта/лицензия/возвраты/обновления совпадают в RU/EN и quote.
- Пройдены owner/non-owner, overlap, повторные/out-of-order webhooks, delayed payment, refund, истёкшая сессия, законченный update window, revoked release и safe remediation.
- Pro не находится анонимно в HTML/RSC/maps/storage/CDN; содержимое публичного runtime демо не выдаётся за защищённую тайну.
- Реально проверены восстановление БД/заказов/grants и откат релиза; мониторинг и ответственный дежурный определены.
- Публичные ограничения, время поддержки и operational targets соответствуют доступным ресурсам команды.

Первое включение оплаты — ограниченный rollout с возможностью остановить новые checkout без остановки docs/Free и без потери уже принятых webhook. Автоматизация не удаляет историю финансовых событий при откате приложения.

## 10. Поддержка и постоянная эксплуатация

Классы обращений: ошибка содержимого/верстки, несовместимость среды, проблема доступа/оплаты, ошибка перевода, сообщение об уязвимости. Минимально запрашивать ID/версию элемента, среду, browser и воспроизведение; не просить целый приватный репозиторий, токены или платёжные данные.

Исправление подтверждённого дефекта элемента входит в обслуживание поддерживаемой версии; индивидуальная разработка сайта и конвертация на неподдерживаемый стек не включены в обычную поддержку. На странице support это сказано до покупки. Не обещать 24/7 или персональную установку при отсутствии соответствующего ресурса.

Еженедельно при наличии пользователей: разбор ошибок экспорта и платежей, невыданных прав, времени ответа, возвратов и поломок переводов. Периодические проверки: backup restore, ревизия зависимостей, проверка sample bundles и источников лицензий. Конкретные интервалы и аварийные сроки согласованы с ИБ-приложением.
