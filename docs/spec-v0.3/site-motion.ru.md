# Авторская motion-система нашего сайта v0.3

Статус: требования к дизайну и будущей реализации. Сайт пока не реализован; ниже нет заявления об уже работающих анимациях. Документ дополняет [дизайн v0.2](../spec-v0.2/design-and-layout.ru.md) и заменяет его строку motion-токенов оболочки. Контентный раздел — [motion-catalog.ru.md](motion-catalog.ru.md).

## 1. Характер движения

Движение сайта должно объяснять путь **«выбор → настройка → исходник → готовый комплект»**. Рабочий мотив: чёткая акцентная линия, связанный кадр и короткая сборка элементов. При смене состояния сохраняется визуальная опора: активная карточка, место параметра, размер кнопки или область исходника.

Авторский характер создаётся композицией, графикой, темпом и связью состояний. Fade, FLIP, underline и другие общие приёмы не объявляются изобретёнными нами или гарантированно уникальными на рынке. Каждое фирменное взаимодействие имеет свой storyboard и оригинальные детали; финальный вид проверяется на прототипе.

Оболочка остаётся рабочим инструментом. В ней нет заставки перед доступом к каталогу, перехвата скролла, курсора вместо системного pointer, постоянных декоративных циклов и ожидания анимации ради выполнения действия. Выразительные большие эффекты демонстрируются внутри выбранного preview.

Сайт может использовать собственные коммерческие рецепты как свои исходники. Это не снимает закрытую выдачу исходных комплектов посетителям. Исполняемый JS интерфейса доступен браузеру; DRM или невозможность восстановления поведения не обещаются.

Если сайт и каталог используют один модуль, указать `itemId + itemVersion` в внутреннем motion registry. Если реализация сайта только вдохновлена рецептом и отличается, показывать связь как пример применения; нельзя заявлять равенство исходников без фактического общего source.

## 3. Токены и ограничения

Проектное предложение для оболочки; окончательные значения проверяются на реальном прототипе.

| Токен | Значение | Применение |
| --- | --- | --- |
| `motion.instant` | `0ms` | Off, fallback и мгновенные смысловые изменения |
| `motion.feedback` | `120ms` | Нажатие, смена иконки, bookmark |
| `motion.state` | `180ms` | Выбор, смена короткого текста/подсветки |
| `motion.panel` | `240ms` | Mobile Studio, menu/sheet |
| `motion.composition` | `320ms` | Сетка, общий кадр, файловый мотив |
| `motion.demoMax` | `480ms` | Верхняя граница отдельного перехода demo; циклы описываются отдельно |
| `distance.micro` | `2px` | Короткая обратная связь |
| `distance.control` | `6px` | Небольшой сдвиг деталей |
| `distance.panel` | `12px` | Смена панели оболочки |
| `ease.standard` | `cubic-bezier(.2,0,0,1)` | Основной отклик |
| `ease.exit` | `cubic-bezier(.4,0,1,1)` | Короткое завершение/уход |

Без bounce и spring overshoot в оболочке по умолчанию. Easing и длительности подстраиваются общей системой, не отдельными случайными значениями в каждом компоненте. Связанный кадр может перемещаться дальше 12px по реальной геометрии, но это ограниченный переход WM03 с прямым fallback, а не разрешение крупного движения всем panels.

Default shell policy: `subtle`. Пользователь может выбрать `off` в настройках движения; эта настройка относится к оболочке, отдельно от пресета выбранного контента. Системный `prefers-reduced-motion: reduce` приоритетнее обоих. Для оболочки в reduced mode пространственное и декоративное движение отключено; короткая opacity допустима только без потери смысла и комфорта. Смена системной настройки учитывается в текущей сессии.

## 4. Общий runtime-контракт

- Нативное действие, актуальная информация и accessibility state обновляются независимо от завершения анимации.
- Быстрый повторный ввод заменяет текущий переход. Очередь проигрывания старых кликов/состояний не накапливается.
- Интерактивный DOM соответствует реальному состоянию; выходящие слои не остаются tabbable/clickable. Декоративный overlay имеет `aria-hidden` и `pointer-events:none`.
- Не переписывать чужой transform на корне компонента: использовать согласованный wrapper/слой или композицию свойств.
- Отмена перехода, unmount, router interrupt, resize, locale change, font load, скрытая вкладка и уход за viewport обрабатываются явно.
- В React Strict Mode повторный mount не удваивает subscriptions; cleanup отменяет собственные animations/RAF/observers/listeners и не удаляет стили другого экземпляра.
- Клавиатура и touch получают понятный результат без обязательного hover/drag. Focus и hit area не анимируются от пользователя.
- Все network/export/payment ошибки имеют самостоятельные состояния. Motion никогда не изображает подтверждённую оплату, сохранение или скачивание раньше факта.

## 5. Производительность

Motion оболочки не увеличивает исходный бюджет 200 KiB gzip initial JS каталога автоматически. Новые библиотеки требуют отдельного ADR и измерения; рабочая база — CSS/Web Animations API, переносимые локальные helpers. Demo/editor/exporter по-прежнему загружаются отдельно по необходимости.

В каталоге одновременно активно одно демо; остальные карточки используют постеры. Основные UI-контролы могут иметь короткий CSS feedback без независимых постоянных loops. Неактивные preview и hidden tab останавливают декоративную работу. Измерять анимированный и статический вариант на одной странице и одном устройстве.

До публикации отчёт содержит build delta, long tasks, frame-time p95, используемое устройство, сценарий быстрых действий и память до/после повторных переходов. Универсальное «60fps на любом устройстве» не используется. При ухудшении ввода или скролла сначала упрощать движение, а не менять бюджет незаметно.

| ID | Условие |
| --- | --- |
| SITE-M-01 | P0 storyboard и итоговая реализация WM01/02/04/05/08 согласованы на реальном RU/EN контенте. |
| SITE-M-02 | Выбор, URL, focus и действие не ждут motion; при неработающем runtime остаётся обычный интерфейс. |

| SITE-M-07 | Быстрое повторение/отмена/resize/locale change/unmount не оставляют очередь переходов или активные ресурсы. |

| SITE-M-09 | Демонстрация рецепта на сайте связана с правильным release; маркетинг не обещает доказанную глобальную уникальность общих приёмов. |
