# Исправления по аудиту логики Tallshift

26.10.2026. Продолжение [аудита](product-logic-audit-2026-10-26.ru.md). Исправления внесены в исходники, собранный review-стенд и актуальное ТЗ. Визуальная приёмка пользователя остаётся отдельной; production backend не подменяется локальными моделями.

## Что исправлено

| Область | Реализация |
| --- | --- |
| Невалидный/неприменённый цвет | Поля сообщают состояние draft; Copy code/prompt, ZIP, выдача отдельного файла и экспорт конфигурации блокируются до Apply/отмены. Есть возврат к применённому цвету. Поля в рабочей области и разделе основ используют общий черновик, без скрытого расходящегося ввода. Объяснение связано с действием и видно у настроек |
| Длительность | A001 использует общие лимиты в `recipes/state-relay/config-limits.ts`: целые 0–480 ms, шаг 1. Контрол, валидатор и генерируемая schema согласованы; 35/470/480 экспортируются без обрезки. Невалидный ввод блокирует экспорт активной анимации; Off экспортирует 0 |
| Промпт | Выбор «Сохранить дизайн / Адаптировать под проект»; выбранный режим используется и в копируемом тексте, и в ZIP. Название режима переведено. Все три языка и обе цели интеграции сохранены |
| Инструкция | Постоянная кнопка рядом с действиями рабочей области открывает текстовую панель с инструкцией выбранной локали и target. Она рендерится как текст/код без raw HTML и дублирования INSTALL/INTEGRATE. В ZIP остаются все инструкции |
| Контекст проекта | По умолчанию выключен, поле скрыто. До 4000 символов; введённый текст сохраняется в памяти страницы, но исключается из промпта/ZIP при выключении. Ничего не отправляется в LLM/сеть автоматически |
| Типы каталога | Три верхних типа: секции, компоненты, анимации. Эффекты E и сценарии A входят в общую группу анимаций; внутри неё отдельный фильтр вида. IDs и состав покупок не менялись |
| Названия | Paid / Платный / Trả phí вместо отдельного пользовательского «Pro». «Набор настроек» вместо «пресета», с указанием хранения на странице. All packs явно содержит 4 текущих набора, 23 уникальных платных материала |
| Доплата и сроки | Сводка показывает цену новых материалов отдельно от прежнего состава и его дат обновлений. Старые даты не продлеваются. Есть обзорные сценарии: первая покупка, купленный Product, истёкшие обновления, 17 материалов после возврата Product |
| Доступ | Добавлены checking, provisioning, partial, updates-expired, delivery-error. `deriveAccessState` различает неизвестные права, ожидание оплаты, оплаченную подготовку доступа, частичный состав, окончание обновлений и сбой выдачи. Истечение обновлений/ошибка скачивания не предлагают оплатить уже принадлежащий состав снова |
| Данные покрытия | `summarizeCoverage` группирует проверенные действующие права по датам, выбирает позднюю дату при пересечении и не придумывает отсутствующую. Непроверенная история блокирует расчёт платной сводки |
| Контракты языков | A001 config поддерживает VI; текущий planned manifest и названия 32 материалов/6 предложений/8 категорий в реестре включают VI. Исторические RU/EN формы читаемы, built/published записи должны включать три языка |
| Верстка | Инструкция и основное действие собраны в одну панель, боковые отступы общие на адаптивах. Состав заказа раскрывается отдельно, даты прежних покупок видны без чтения списка из 17 названий. Select пересчитывает положение при прокрутке, сохраняя открытый выбор, пока триггер виден |

Основные файлы: `prototype/src/foundations/SystemStudy.tsx`, `SystemColorControl.tsx`, `SystemMotionControls.tsx`, `SourceNavigator.tsx`, `AccessStatesLab.tsx`, `SystemEntitlementState.tsx`, `access-model.ts`, `workbench-state.ts`, `DiscoveryLab.tsx`, `discovery-filter.ts`; исходники A001 и локализации. Модели доступа экспортируются из локального пакета `@tallshift/ui` для будущего адаптера; они не предоставляют серверных прав.

## Проверено

- Unit/semantic проверки библиотеки и регрессии логики: 126/126.
- Экспорт: 12 комбинаций EN/RU/VI × Next/Vite × два режима; совпадение source/prompt/ZIP, детерминированность и checksums. Отдельно 35/470/480 ms.
- TypeScript и сборка review-стенда. Сборка и установка упакованной библиотеки в независимые Next.js/Vite consumer-проекты.
- JSON Schema и planned fixtures: 8 схем, 61 проверка; это проверка формы контрактов, не выпуск Pro-контента.
- Браузер: ошибочный и неприменённый HEX блокируют Copy/ZIP; Apply обновляет исходник; отмена возвращает выдачу. Контекст включается/исключается, Adapt меняет текст; инструкция открывается, в том числе на VI. 480 и 35 ms допустимы, 480.5 блокирует выдачу.
- Браузер: Product за $16 → All packs $23, 17 новых материалов, 6 прежних с собственной датой; истёкшая дата явно отмечена. Селектор сценария доступен с клавиатуры и мышью.
- EN 320px, RU 390px, VI 768px: без горизонтального переполнения страницы; боковые направляющие рабочей области синхронизированы. Это целевые проверки новых изменений, не полная ручная приёмка всей дизайн-системы или всех сочетаний устройств.

## Что дополнено для production и остаётся отдельной реализацией

[Серверный контракт сценариев](commerce-integration-scenarios.ru.md) конкретизирует quote expiry, повторный checkout, paid без готового grant, поздний webhook после закрытия окна, duplicate/out-of-order события, возвраты, сбой выдачи и восстановление покупок. Для каждого заданы поведение и приёмка.

В репозитории пока нет production auth, платёжного adapter/merchant, durable ledger, приватной выдачи Pro и готовых файлов всех 32 материалов. Они не становятся готовыми из-за этих исправлений. Продажи остаются выключены. Seller/MoR, налоги, условия возвратов/хранения и инфраструктура должны быть определены и проверены до подключения оплаты. Локальный сценарий покупателя — только review fixture, никогда не источник реальных прав.
